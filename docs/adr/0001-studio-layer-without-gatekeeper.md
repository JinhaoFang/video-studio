# 工作室层不设人工把关

2026-11-09，用户定（spec #128）。

第一次有协作者用本仓库做完一期（PR #121）。他在制作会话里直接写了"沉淀"：把立场、只在本机成立的数字和无法复现的步骤写进工作室层，7 分钟后自己合并。我们决定**不**因此设一个审批人，也不区分所有者和协作者：被邀请进来的人都是用户，都能改工作室层。工作室层的质量靠三件事保证：沉淀只从新会话的 `/retro` 进入；沉淀要满足四条标准（只写事实和方法、换人换机器仍成立、能复现、冲突要列出）；改了工作室层的 PR 合并前，在作者会话之外用 `code-review` 审一次。推翻已定事项时，请当初定这条的人确认。做法写在 `docs/workflow/README.md`「复利」。

## 考虑过的其他做法

- **所有者把关**：仓库所有者批准所有工作室层的改动，协作者只能提建议。这样最稳，但会把被邀请来的人当成外人，每次沉淀都要等一个人，被否决了。
- **不设任何约束**：#121 已经说明，制作会话自己写的沉淀容易混进立场和本机事实。

## 后果

- 审查是机器做的，不是人做的；它能查出事实错误和不合标准的地方，但查不出"这个方向对不对"。方向上的分歧靠"推翻已定事项要确认"这一条兜底。
- 合并前审查现在只是规则，没有做成护栏。出现绕过它的实际违例时，再考虑用 CI 检查 PR 上有没有审查结论。
