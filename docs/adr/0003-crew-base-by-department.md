# 剧组底座：按部门组织一期制作

2026-11-26，用户定（`/grill-with-docs` 会话，纯代码动画正片之前）。

一期视频由剧组来做：编剧、美术、摄影、动作、剪辑、声音六个部门，加上设计负责人兼任的导演和制片（`GLOSSARY.md`「剧组」）。各类片子用同一个剧组，不同的只是各部门的做法。原来按阶段排的 13 项清单改成按部门排，并新增 ⑭ 动作。每个部门写明四件事：负责哪些决定、交出什么、交给谁、怎么自查。交接以全片装配为主干：镜头之间看切点表，画面和声音之间看听点表，上游锁定后下游才开工。

**依据**：spec #60 和 spec #147 一共出过三次错，都出在交接处：
- 1.2 秒黑场；
- 切镜时主体从画面约 62% 处跳到约 38%；
- 静默被做成了断音。

按阶段排的清单只回答"要定什么"，回答不了"谁交给谁、交接处归谁负责"。#157 的评价是按色彩、构图、动作、剪辑、声音逐个部门看的，用户认为这种做法更具体、更专业，也适用于所有类型的视频。

**设计负责人的分工**：只亲手做纸面上的决定，包括台本、镜头剧本、色彩剧本、动作规则、听点表和各部门的「绝不能像」，再加上验收和最后的微调；画面默认派出去，定稿也可以派出去迭代。原因是小样里引擎、主角和镜头 1 都由设计负责人亲手做，主会话用掉了全 spec 约一半的 token。

做法写在 `docs/workflow/README.md`「一期视频」。

## 考虑过的其他做法

- **只给 13 项表加「部门」「交接物」两列**：改动最小，但交接、锁定和自查都没有着落，出过错的交接处仍然没人负责。
- **按片子类型启用部门**（例如教程不启用动作）：没启用的部门就没人检查，它的决定会被悄悄跳过。所以改为六个部门每期都在，用不上的写「不适用」和理由。
- **照行业细分，约 10 个部门**（作曲和音响分开，调色、设定各自单列）：每多一个部门就多一处交接，而这些工作在本仓库多半由同一个执行者、用同一套代码完成。行业里的特效拆进动作（特效作画）和美术（光效、颗粒），场记的工作拆进剪辑的切点表和摄影的机位图。
- **照日式动画分工**（原画、动画、背景、撮影……）：只适合动画。
- **按部门给席位配模型**：#157 证明的是作画该用哪个模型，不是美术部门该用哪个模型。模型适不适合，看的是用什么手段做（作画、网页式界面、脚本），所以席位的工作类型和部门分开，工单里各写一行。

## 后果

- 改掉了 #132 "不加新流程、技能或简报文件"里"新流程"的部分，经用户确认：清单换了排法，新旧两套不并存。入口和技能不变，仍不设简报文件：简报里观众的感受归编剧的台本，品质标准和「绝不能像」分到各部门。
- 小样本期约定里的"摄影"模块指日式动画的「撮影」，也就是最后的合成、光效和颗粒，和术语表里的摄影部门（取景、构图、运镜）不是一回事。小样的文档不回头改；新一期把这部分叫作质感，归美术。
- `docs/video/` 还缺遮挡、甩镜等转场、连贯性规则、机位图、动作知识、拟音等条目，由纯代码动画正片 spec 的调研工单补上，每条都附出处。
- 全片装配会让开工时多一张工单，镜头时长也要早定。
