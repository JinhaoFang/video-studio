拆分时怎么做

把 57 项收成 5 条思路和一组机制。以后再遇到问题，先记成观察，分析根因、看现有思路能不能覆盖、比较做法，再选最轻的形式（一句思路、一个脚本、或者不加），用过之后再评估。

1. 验收回到原问题

做完不等于解决：收尾按 spec 写的原问题重新测一遍，没达到的写明，不以“实现了要求”代替。

W16W33W47
2. 每个节点重新判断资源和做法

派发、合并、审查前看名额、远端状态和机器负载，再决定并行还是串行；长作业交给巡检工具。

W42W43W44W31W32W56
3. 规则按“换一个人或一台机器还成立吗”归类

事实只存一处，别处引用；个人习惯不进仓库；路线图只放方向和决定。

W8W45W46W47W48W51W57
4. 给人的产出按人的读法设计

先放要你做的和结论；要你记数字再比较的地方用图；证据放在结论旁边；明细折叠。

W36W40W34W39
5. 验证范围跟着改动的影响走

开发时只跑相关测试和静态检查；完整验证在合并点跑一次；只改文档的只跑静态检查；spec 收尾再跑一次全套。
