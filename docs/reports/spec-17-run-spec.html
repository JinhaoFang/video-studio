合并以后

执行一个 spec 的流程

步骤只写在执行技能 run-spec 里，本仓库特有的值在 docs/agents/run-spec.md。下面是合并以后，从想法到合并的完整路径。

1
想清楚、写 spec、拆工单 用户触发
/grill-with-docs → /to-spec → /to-tickets，在讨论用的会话里完成。
2
开新会话，说"执行 spec #S" 用户触发
设计负责人进入集成分支 spec/<S>-<短名>。新会话让设计负责人的上下文保持小。
每一轮，直到所有工单关闭
3
选出可做的工单 脚本
frontier <S> 把工单分成可做、被阻塞、已关闭三组。
4
分流与派发 设计负责人 Codex
设计工单自己做、提交；工程工单用 dispatch <T> 在后台派出，Codex 在自己的 worktree 里做，几张工单并行，做完会通知。
5
验收 设计负责人
读 Codex 的汇报，自己跑验证、看验收产物，逐条处理 TODO(design) 和推断清单。
6
合并、写回 脚本
land <T> 合进集成分支并收拾 worktree；accept <T> 写验收评论，自动附上用时和 token，通过就关闭。
7
按批审查 Codex
这一轮的工单都合并后，派 Codex 审查；要修的开返工工单，回到第 3 步。审查期间可以继续派发，但不合并。
8
收尾 Codex 设计负责人
Codex 审查整个分支 → 返工做完 → 开 PR → 写 HTML 汇报并发布链接 → cleanup <S> 清理本地中间产物。
9
审核汇报和 PR，合并 用户
只用 merge commit，每个提交和它的 Refs 都留在 main 上。

改之前：一张工程工单，手工近 10 步

  1. 起英文短名，建 worktree 和分支
  2. 接两个软链接
  3. 装依赖
  4. 拼一条带 worktree 说明的长派发命令
  5. 从进度文件抄用时和 token
  6. rebase 到集成分支
  7. 跑验证
  8. 快进合并、推送
  9. 复制派发记录和验收产物
  10. 删 worktree 和分支

改之后：三条命令

tickets.ts dispatch <T>tickets.ts land <T>tickets.ts accept <T> …

名字由脚本决定，不用起短名；land 中途停下，修好后重跑同一条命令就能接着做；收尾用 cleanup <S> 一次清理。

交付

做了什么

  • 两条命令走完一张工单dispatch 建 worktree、接软链接、装依赖、派给 Codex 并等它结束；land 依次 rebase、验证、快进合并、推送、复制记录、删 worktree。
  • 过程数据自动留在 GitHubaccept 把每次派发的用时和 token 写进验收评论，清理本地以后写汇报照样有数据。
  • 收尾一条命令cleanup <S> 只删本 spec 的记录、产物、worktree 和分支，其他记录保留。
  • 文档不会悄悄过时规则文档里写了不存在的 pnpm 脚本或 node 路径，pnpm verify 和 CI 都会失败。
  • 可迁移技能目录不再引用 tools/；本仓库特有的值在 run-spec.json 和 run-spec.md，后者写了迁移步骤。
  • 汇报改成可视化页面你审核 PR 时提出的要求：汇报从这一期起是 HTML 页面，要求写进了汇报规范。

问题与处理

包括我自己的失误

  • 读工单的命令一直是错的，我漏看了信号 已修 #29

    派发指令和工程负责人角色文档写的是 gh issue view <号> --comments，在 gh 2.83 上它只输出评论，不输出正文。spec #1 起的每次派发都受影响，Codex 每次都自己改用 JSON 读取，所以没出事。会话一开始我就遇到过一次空输出，#21 的汇报也在「偏离说明」里写了，我都没追，直到收尾审查才查出来。教训：汇报里的「偏离说明」要当作信号来查。

  • 验收评论里写错了两个数字 已更正

    #21 的用时误写成进度日志里的时间戳（约 23 分钟），实际是 7.1 分钟；#23 的缓存数少了千位分隔符。这也说明让 accept 自动取数（#22）是对的。

  • 审查期间往集成分支提交了 #24 无影响

    违反了"审查跑完前不合并"。第三批审查把起点时的提交定为终点，#24 没有混进这一批，由收尾审查覆盖。

  • 本机 pnpm 的版本看起来对不上 已查清

    本机全局装的是 pnpm 12.9.1，进入仓库后按 packageManager 切换到 10.34.6；pnpm help --all 由全局的 12.9.1 处理，所以报错。这是正常的版本切换，不用处理。
