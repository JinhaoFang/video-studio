改之前：复制本机的迁移包，手工十几步

  1. 复制技能目录，确认它进 git
  2. 照示例写执行配置，逐项改值
  3. 复制配置说明，删掉来源仓库特有的内容
  4. 把工单约定追加进工单文档
  5. 加忽略规则（软链接目录不能带斜杠，迁移包里没写原因）
  6. 建执行角色标签
  7. 对齐规则文档
  8. 按自检清单手工逐项核对

迁移包是一份快照，来源仓库改进以后要重新打包、重新复制。第一次手工迁移碰到 14 个问题。

改之后：一条命令，加一个技能

npx skills add JinhaoFang/video-studio \ --skill run-spec --skill setup-run-spec -a claude-code -y/setup-run-spec

两个技能只装进 Claude Code 的技能目录，不进 git，Codex 看不到。/setup-run-spec 只能由用户手动运行：先自检、查看、讲清步骤，用户确认后再写配置、工单约定、忽略规则、标签和合并设置；规则文档在对话里一起改；最后自检，派 Codex 做冒烟测试。更新就是重新运行安装命令。

流程发现

这次学到的

  • 执行要放在新会话里，哪怕是同一个人接着做

    工单里已经写清了上下文，执行不需要对齐时的对话。放在长会话里，设计负责人的缓存读取约为 Codex 输入的 4.5 倍，新会话（spec #17）只有 1.3 倍。路线图「下一步」已写明。

  • 纸面推断，三次被实测推翻

    更新命令会保留"只给 Claude Code"、审查认为派发能处理带斜杠的目录、初始化技能能用哈希核对改动，三处都在实测时被推翻。交出去的命令和判断，要先测过再写。

  • 先拆模块再并行，冲突几乎没有

    四张工单同时改工单脚本，只在入口登记表上冲突了一次，两边都保留就行。

  • "先发布、再试用"的两段式可行

    第一个 PR 不关闭 spec，GitHub 合并后自动删除集成分支，run-spec 再从 main 重新建同名分支继续，没有遇到问题。

  • 退出 git 跟踪留下的坑，会反复出现

    Matt 的技能、run-spec 先后退出跟踪，每次都有人在切换分支时把它们删掉。初始化技能现在会提醒，但只能靠人记住"先 fetch 再切换"。
