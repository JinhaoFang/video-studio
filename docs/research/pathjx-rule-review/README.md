## 文档结构

最严重的三处（明细见 C）：

1. **锁定测试集的现行规则没有权威文本**：只在路线图、日志、GitHub 评论里零散出现。建议补 ADR 0002，等评估协议 v2 再并入。
2. **第一版成绩在约 10 份文档里重复抄写**，汇总账本 `reports/model-versions.md` 自己的说明还是旧的。建议只留"研究报告 → 账本 → 对外摘要"三层，其余只引用。
3. **演示文档散在 3 个目录**，`presentation-v1/README.md` 还写着"尚未生成 PPT"。

另外：`roadmap.md:54,58` 还写"等待 PR #206 合并"（已核实，路线图是新会话的入口）；文档地图漏列 `engineering/diagrams.md`、`agents/domain.md`；三个过长文件（`development.md` 51 KB、评估协议 37 KB、MVP 方案 50 KB）各混了多个主题。

**硬约束**：评估协议和三份门槛文件被锁定工具按路径和字节核对，内容和位置都不能直接改，只能在外面加有效版本说明，迁移等协议 v2。

## 用户裁决（10-30）

- **标准第二版**：2、3、5 条按建议（已安装且锁定哈希的技能算覆盖者；另立"记录"一类，移到日志或研究目录；agent 阻塞还是轮询归仓库规则）。
- **锁定测试集**：按 10-25 放宽后的规则，不限制死。放宽的原因是只跑一次太死，没有其他数据，测试后无法继续调优。记成 ADR 0002，评估协议 v2 再并入；ADR 0001 和设计负责人文档里的"只运行一次"改掉。
- **临床措辞**：设计负责人出方案，用户最终决定。`clinical-wording.md:5` 为准，`roles/design.md:43` 的例外收窄，不再包括界面临床措辞。
- **甲状腺对外说法**：统一为"跨院适配"。
- **Codex 并发名额**：两台机器统一 3 个，写进 `run-spec.json` 的 `codexConcurrency`，不再按机器设环境变量。
- **演示运行时**：可以跑完整检查，演示手册的禁止删掉。
- **总原则**：现场参数（并发数、磁盘余量、超时、预算）会随情况调整，不写成定死的规则。只有严格的项目规范和防止项目混乱的约束才是仓库规则；参数集中放一处（配置或一节说明），规则只引用不复述。这一条进标准第二版。

还要查的两点：

- **两条线**：PathJX 的产品工程线和算法与数据线是项目自己的分工，不是 workflow 的设计；workflow 能直接适配它，说明泛化性好。但两条线的文档有重复和混乱，代码的情况还不清楚。明细见 `review-E-two-lines.md`。
- **结果报告**：`journal/`、`roadmap.md`、`reports/` 等同一结果写了好几处，消耗注意力。明细见 `review-F-results.md`。

## 两条线（明细 E）

文档问题 11 个、代码问题 10 个（高 3、中 4、低 3）。

- **"线"的定义不统一**：`repository.md:13`、`roadmap.md:15` 按领域分（产品工程／算法与数据），`run-spec.md:47`、`roadmap.md:43` 按机器和会话分。可 spec #73 在算法线机器上实现了产品插件，演示也在那台机器上做，两种判法归属不同。描述分工的地方有 9 处，措辞各异，`README.md:36` 和 `apps/README.md` 已过时。
- **共用登记处没有唯一清单**：`run-spec.md:45` 和 `:49` 各列一份，交集只有两项，都漏了检查器强制登记的项。核心库的"公开接口"没有边界：`__all__` 导出 46 个名字，另有 4 个未导出的名字被两条线直接导入。
- **代码：训练和推理没有共用推理实现**，和 `AGENTS.md:8` 相反。logistic 任务头推理 4 份，任务头 NPZ 读取 5 份，按框过滤 2 份且成员判定不同（`tissue_filter.py:379` 对 `postprocessing.py:144`），核心库内部两套特征缓存格式、缓存键不兼容。已核实：打包用的"独立参考" `tools/model_package_reference.py:42-74` 和产品插件 `python/tasks/src/pathjx_tasks/__init__.py:46-74` 只差分支顺序和维度检查写法；参考实现本应单独实现、用来互相校验，复制过来的校验不出共同的错。
- GPU 锁在 3 处各写一份、路径写死，产品执行器自己不持锁；演示、打包和 shell 编排写死了算法线机器的绝对路径。`tools/` 没有死脚本。
- 建议：`repository.md` 当两条线共用部分的唯一权威（线的定义、牵头表、登记处总表、协作方式）；每条线一页只写本线独有的；每台机器一页环境说明，和线分开。
