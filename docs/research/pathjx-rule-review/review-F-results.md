## 1. 结论

**抽查的 6 个结果，每个出现在 10–30 处，平均约 19 处；其中 4 个结果的说法有不一致，2 个结果的权威入口指错或缺失。** 统计口径是"包含该结果核心数字或结论的不同文件，加上 GitHub issue 和 PR"：第一版结直肠成绩 22 处、甲状腺校准 30 处、基础模型选型 16 处、第一次院方演示 13 处、spec #194 整理 10 处、10-29 存储清理 8 处（这一项其实是两次清理，被写成了一次）。

数字本身基本一致，问题出在说法、状态和指向上：

1. **数字一致，但每处都要重新加限定语。** 34/34、105/143 和 107/143 在 18 份文件里抄写，各份都用不同的话补"不能把 107/143 写到过滤版名下"（例如 `docs/design/landing-page/claims.md:26`、`docs/research/data-model-validation/20261026-demo-evidence/README.md:23`、`docs/demo/presentation-v1/evidence.md:41`）。这说明抄写本身就是风险源。
2. **甲状腺"跨院适配"的改名只改了演示材料。** 10-27 用户要求改名（`docs/journal/2026-10-27.md:24`），10-29 的 PR #190 只改了 `docs/demo/presentation-v1/`（`docs/journal/2026-10-29.md:35`）。对外摘要 `docs/reports/first-version-summary.md:53,70`、账本 `docs/reports/model-versions.md:72,149` 和 spec #73 汇报 HTML 仍写"本院校准"。同一份摘要里，`:14` 写"青海公开数据集"，`:53` 又写"本院校准版"。
3. **测试集用了第几次，两种说法并存。** 冻结的门槛补充写"第二次打分（另有一次校准读取）"（`docs/demo-gate-thyroid-calibrated.md:23`），其余各处写"第三次使用"（`first-version-summary.md:53`、`guides/data-model-evaluation/model.md:212`、`demo/presentation-v1/ppt-handoff.md:42`）。账本要专门用一行解释（`model-versions.md:202`）。
4. **路线图把两次清理指成一次。** `docs/roadmap.md:25` 写"未选中三个编码器的特征已删除（10-29）"，链接的却是 `reports/storage-cleanup-20261029b.md`。这份是 #203 删除 19 项、释放 229 MiB 的回执，里面没有编码器特征。真正删掉 22.09 GiB 特征的那次清理没有仓库内报告，只出现在 `journal/2026-10-29.md:13,26`、`engineering/local-assets.md:145`（链接到被忽略的本机 JSON）和 `reports/spec-194-phase-1-cleanup.html` 里的 `"earlier"` 数据块。
5. **演示的日期和页数各处说法不一。** 日志日期表把 10-27 的 15 页版称为"终版"（`journal/README.md:17`、`journal/2026-10-27.md:23`），而 `final-deck.md:3` 说实际使用的是 12 页版，10-29 10:34 保存。10-27 的日志通篇没有记录演示"已举行"，`:27` 还写"材料等待用户内容审阅"。第一阶段的结束日期，路线图写 10-29（`roadmap.md:48`），MVP 方案写 10-27（`MVP 方案.md:27`）。
6. **基础模型选型最集中**：ADR 0001 是权威，其余 15 处都和它一致，只有 `adr/0001-foundation-model.md:53` 的"只允许运行一次"已经过时（C 的 T1）。这说明"决定写进 ADR，别处只写一行指针"的做法有效。

**注意力成本**：设计负责人的新会话按 `AGENTS.md`、`roles/design.md` 和 `roadmap.md` 的指引开工，会被引到约 **188 KB** 的结果类文本（10 份文件加 MVP 方案的一节），估计其中 **约 80 KB（约 43%）是重复、过时或和开工无关的历史**。路线图本身 19.5 KB，估计 44% 可以移走。

## 5. 建议

### 5.1 每类文档的职责（一句话）

| 文档 | 职责 |
|---|---|
| `roadmap.md` | 现在往哪走、正在做什么、下一步、阻塞下一步的待定问题；已定的事每行一句加一个仓库内指针。目标 ≤ 8 KB。 |
| `journal/` | 当天发生了什么、谁决定了什么，全部链接到出处；不是权威，不抄成绩表，不定规则或口径。 |
| `reports/spec-*.html` | 每个 spec 一份收尾汇报；合并后写回一次最终状态，之后冻结。 |

| `reports/storage-*.md` | 每次清理一份回执；`local-assets.md` 只放索引。 |

### 5.2 去重规则（数字只写在哪里）

1. **病理指标**：一手结果写在研究报告；跨版本汇总只写在 `model-versions.md`；对外表述只写在 `first-version-summary.md`（它可以抄数字，因为它是对外的唯一出口）。其他文件（讲解、日志、路线图、院方材料、介绍页、MVP 方案）只链接到账本的锚点，不抄表。院方材料和介绍页在发布时需要自带数字，那就作为冻结快照，文件头写"快照于某日，数字以账本为准"。
2. **工程和存储数字**：只写在对应的回执报告或 spec 汇报里；`local-assets.md`、日志和路线图只链接。
3. **对外用语**：只写在一份对外口径文档里（C 的 T14），包括"本院校准→跨院适配"和"第二次打分与第三次使用的换算"。冻结文件里的旧用语列为"历史用语"，不改原文。
4. **现行规则**：不能只写在日志或 issue 评论里。日志里出现"一律、约定、不再"这类新规则时，当天就要同步写进对应的规则文档，日志只链接过去。
5. **固化成检查**（遵照"确定性规则交给系统"）：在 `make check` 里加三条。
   - 禁用词检查：除冻结范围外不得出现"本院校准"或"本院适配"，冻结范围沿用 `tools/moved-paths.json` 的做法登记。
   - 路线图体积和格式：总长不超过预算；"已定"每格不超过约 200 字；"写在哪"一列必须是仓库内路径，不能只写 issue 评论。
   - 路线图里"进行中"提到的 PR 已经合并时报警（C 的 T10）。
