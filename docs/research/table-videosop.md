视频旁白里补充了几条仓库没写的：

- 干活的 agent 是 **Codex**；生图放在 ChatGPT 网页端做，一是质量比 Codex 里好，二是省 Codex 额度；生视频用 Google Flow，也是为了省钱。
- 选 Remotion 而不是 HyperFrames，是因为复杂运镜和景深更强；ChatCut 只用来剪配音、出字幕，再在可视化时间线上手动调。录屏用开源的 Recordly。
- 开场单独做：在 ChatGPT 里把思考强度拉到 Pro 出方案，**第一版直接否掉让它自己反思**，第二版再细看，定了之后整理成交给 Codex 的 MD 文档。
- 作者说的最大限制：时间轴以配音为准，改配音后动画、音效、字幕都要重新对齐、重新渲染，让 agent 来回改很费 token；用 Computer Use 操作剪映 / 达芬奇还在测试。

## 1. 这套流程是什么

- **一个总控对话 + 多个分段对话**：第一次对话当总控，负责整期规划、采用记录、总装；之后每个分段开一个新对话，只写自己的专属目录。
- **配音是时间基准**：先定稿件和配音，再出"制作大段表"（D01、D02…按叙事任务划段，不按秒数切）。
- **DESIGN.md 靠测试建立**：先出静态候选（配色、字体、构图）让人选，再做动态测试（运动方式，参考迪士尼 12 条动画原则），两项都确认后才整理成规范。
- **镜头剧本**：出设计图之前，先把每段"观众怎么看"写成一页（主体怎么变化、镜头怎么带人看、哪里停下来读）。
- **新类型才做样片**，同类型段落对标已确认的片子；交片前跑 `tools/motion-check.ps1` 查长时间静止和一闪而过。
- **生成式素材人手动做**：生图在 ChatGPT、生视频在 Google Flow，由人提交、抽卡、选片；Agent 只准备提示词、参考分工和收片检查。
- **混音有数值目标**：视频里展示的是人声 -16 LUFS（±1 LU）、BGM 走 ducking、音效峰值约 -18～-12 dBFS（以仓库 `docs/06_音效与配乐_可选.md` 为准）。
- **期末复盘**：用人的原话记录返工，区分"规则没写"还是"写了没执行"，满意的画面登记为以后的对标片。

## 3. 可以借过来的东西

重建 NASA 流程时，这几样可以直接补进来，和双角色分工不冲突：

1. **镜头剧本**：设计负责人写分镜时，按"主体怎么变化 / 镜头怎么带人看 / 阅读停顿"写，比只列画面内容更好验收。
2. **动作与声音标记**：每个镜头以 `00:00.000` 为起点标动作秒点，后面音效对点直接用。
3. **动态自检**：查长时间静止、一闪而过的变化，可以做成工程负责人的验收工具（原脚本是 PowerShell，需要改写）。
4. **混音目标写成数值**：人声、BGM、音效各有响度范围，工程负责人照着混，结果能测。
5. **期末复盘**：每期结束把返工原因沉淀到规则里。

## 4. 经验专题：镜头推进与连续画面

上面几节只依据仓库的 README 和 `AGENTS.md`。spec #60 审片时发现开场推拉被做成了溶解换页（返工 #74），回头读了仓库 `experience/` 下的两篇（2026-10-16 读取，CC BY 4.0）：`镜头推进与转场.md`、`视觉叙事与连续MG.md`。要点如下，已采纳的标出去处。

**已写进规则**（`docs/roles/design.md`「镜头运动」和验收，`docs/workflow/README.md` 镜头剧本的“运镜”列）：

- 避免每次都“入场—停住—换一页”。中间节点可以连续经过，要阅读、比较或留情绪时再停稳。同一场景里重新构图，不需要虚构剪点。
- 静帧轮播、轻缩放、光标独动不能代替主过程。主体和关系要连续演化，不要每句清空画面重搭一页。
- 整图缩放是推拉的二维近似；框不动、只放大框内内容是界面缩放，不算推拉。
- 每个镜头写清跟谁、揭示哪里、何时停下或交接视线，在出设计图前写进镜头剧本。
- 静态图确认不等于运动效果确认。要抽查起止、切点两侧和明显变换的中间帧，看跳位、露底、错误裁切和闪帧。

**留作参考，用到时再定规则**：

- **运动匹配剪辑**：两个镜头以相近的屏幕运动承接。先配成一对，再在切点对齐主体的位置、大小、方向和速度。后镜接着前镜的运动继续，再减速落稳，不从零重新起步。缩放匹配要围绕同一视线落点，缩放中心不跳位。
- **运镜方式按表达目的选**：推拉、横移/升降、摇、环绕、视差、变焦、焦点转移、滑动变焦、手持抖动，各有适用任务和前提。环绕、穿行、视差需要有深度的素材，不能用整图缩放冒充。
- **情境表**：依次比较、对象交接、反复受阻、从局部到整体、情绪转折，各列了优先考虑的镜头安排和必须保留的信息。
- **镜头衔接**：共享元素连续演化、图形匹配、动作匹配、遮挡过镜、J/L Cut。“加了转场”不能代替段内的观看设计。
- **完整过程参考**：借鉴整段动作组织，不只复制一个转场或弹跳；登记成熟范例要有确认片的路径、区间和源码。
- **返修**：先把问题落到实际时段和可见症状，再区分是方案、时间组织、参数还是工程问题；每轮优先处理 1～2 个主要问题，不用同一平淡方案的多套参数冒充不同设计。
